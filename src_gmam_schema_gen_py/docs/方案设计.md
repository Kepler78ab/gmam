## 0. 先澄清：只传 name 会怎样？

这里分两种「只传 name」：

### 0.1 `values` 里只有字段名、没有有效内容

- schema 已定好各字段 `length`  
- `values` 不传该 key，或传空串且 `MissingPolicy::TreatAsMissing`  

→ 该字段填 **missingFill**（Chars 默认空格，Numeric 默认 `'0'`），**不是**空 `QByteArray`。  
整包仍是定长，看起来像「空白串」，但 `data.size() == totalLength()`。

只有组装**失败**（`errors` 非空）时，`build` 才返回空的 `QByteArray`。

### 0.2 schema 里只写了 name、length 仍为 0

→ `length ≤ 0` 的字段不计入 `totalLength`；若全部如此，`totalLength==0`，整体错误，返回空。

**结论**：正常缺值得到的是「定长空白/补零」，不是逻辑上的空串；空 `QByteArray` 只表示组装失败。

## 1. 目标与非目标

### 1.1 目标

做一个桌面小工具，让用户：

1. **打开**已有 schema 的 txt → **格式校验** → **表格复现**  
2. **编辑**单元格（下拉枚举 / 数字 / 字符）  
3. **增行 / 删行**（可选：上移下移）  
4. **保存**：覆盖当前文件，或另存为新文件  
5. **新建**空白 schema  
6. （建议）**导出 C++ 片段**：生成可粘贴的 `QVector<FieldDetail>{ ... }`，方便给会写代码的人  
7. 提供 **`build_exe.py`**：用 PyInstaller 打成单文件 exe  

### 1.2 非目标（本版不做，除非审查要求）

- 直接调用 C++ GMAM 做组装预览（可后续）  
- 从旧 `Structure.h` 自动反推 schema  
- 多语言 / 插件体系

## 2. 用户流程

```text
启动
  ├─ 新建 → 选 kind=data|header → 空表（带列头）
  └─ 打开 .txt → 解析+校验
        ├─ 失败 → 弹窗列出行号/原因，不进编辑
        └─ 成功 → Treeview/表格展示
编辑（改单元格、增删行、调顺序）
  ├─ 保存 / 另存为 → 再校验 → 写 txt
  └─ 导出 C++ → 生成片段到文本框或剪贴板
打包：python build_exe.py → dist/GmamSchemaGen.exe
```

## 3. 界面草案（Tkinter）

```text
┌─ 菜单：文件(新建/打开/保存/另存为/退出)  导出(C++片段)  帮助 ─┐
├─ 工具栏：[新建][打开][保存][另存为] | [增行][删行][上移][下移] | [校验][导出C++] ┤
├─ 状态：当前文件路径 | kind=data | 行数 | totalLength 估算                    ┤
├─ 主区：ttk.Treeview（或逐行 Entry）可编辑表格                               ┤
│     # | name | type | length | scale | rounding | overflow | ...            │
├─ 底栏：日志 / 校验错误列表（可滚动）                                        ┤
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.1 列定义

#### Data schema（`kind=data`）— 对应 `FieldDetail`

| 列 | 编辑方式 | 说明 |
|----|----------|------|
| name | 文本 | 必填，建议唯一 |
| type | 下拉 | Numeric / Chars / Reserved |
| length | 整数 | >0；Numeric 提示 ≤18 |
| scale | 整数 | 默认 0；非 Numeric 可灰显但仍可存 |
| rounding | 下拉 | Truncate / Round |
| overflow | 下拉 | Error / Truncate / FillChar |
| overflowFill | 单字符或转义 | 见格式说明（`9` / `\0` / `\s`） |
| align | 下拉 | ByType / Left / Right |
| padFill | 单字符或转义 | `\0`=按类型默认 |
| missingFill | 单字符或转义 | 同上 |
| missingPolicy | 下拉 | TreatAsMissing / EmptyIsValue |

#### Header schema（`kind=header`）— 对应 `HeaderField`

在 `type` 后多一列 **offset**（整数 ≥0），其余同 data。

### 3.2 编辑体验

- 表格行内嵌 Combobox / Entry；「增行」直接插入带默认可选项的一行  
- 枚举列显示：`英文码 — 译文`（译文来自 `./lang/*.json`）  
- 新建 kind：单选 data / header  
- 列宽统一 grid，表头与单元格对齐

## 5. 校验规则（打开/保存时）

1. 文件头：`# GMAM Schema` + `kind=data|header` + `version=1`  
2. 列数、列名与 kind 匹配  
3. 每行：枚举值合法；length 为正整数；Numeric 的 length>18 时警告（可配置为错误）  
4. name 非空；同文件内 name 重复 → 警告或错误（建议：**错误**，避免 QHash 覆盖）  
5. header：offset≥0；可选检查行间区间重叠（警告）  
6. 字符列：只允许单字符或约定转义（`\0` `\s` `\\`）  

校验失败：不静默截断，列表展示「第 N 行：原因」。

---

## 6. 与 C++ 的对应关系

| 生成器列 | C++ `FieldDetail` |
|----------|-------------------|
| 同名列 | 同名成员 |
| 导出 C++ | `FieldType::` / `Rounding::` 等带作用域 |

txt **不是**运行时被 C++ 直接加载（当前 GMAM 无配置文件加载）；  
工作流是：**表格编辑 → 保存 txt 存档 → 导出 C++ → 粘贴进工程**。  
（若以后 C++ 要读 txt，格式已固定，可复用 `format_io` 规则。）

## 7. 打包方案（`build_exe.py`）

审查通过后实现，行为约定：

```text
python build_exe.py
  → 调用 PyInstaller
  → -F 单文件（或 -D，审查可选）
  → -w 无控制台窗口（GUI）
  → --name GmamSchemaGen
  → 入口 main.py
  → 输出 dist/GmamSchemaGen.exe
```

脚本内：检查 PyInstaller 是否安装、工作目录、失败时打印命令便于排查。  
不在方案阶段写入仓库可执行文件。

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 空格/`\0` 在 txt 里难写 | 统一转义：`\0` `\s` `\\` |
| 用户改坏枚举大小写 | 读写规范化；UI 只用下拉 |
| Treeview 单元格难编 | 行编辑对话框为主 |
| exe 体积大 | 可接受；文档说明需本机杀软放行 |

3. 行编辑对话框 + 增删移  
4. 导出 C++  
5. `build_exe.py` + 说明
