# 设计补充 — 可配置策略：心跳与正负应答

> 归属：`module_tcp`（相对通用、可配置）  
> 配套：[analy_01](./analy_01_旧方案tcp模块分析.md) · [analy_02](./analy_02_拆分功能与旧项目对照.md)

---

## 1. 目标

TCP 模块提供**可选的应用层发送策略**（心跳、正负应答等待），默认可关，由参数启用。

- 协议无关：模块**不内置**某厂电文字段拼装（组报仍归 GMAM / 外部）。
- 兼容旧用法：心跳、应答帧可以是**任意已组好的 `QByteArray`**（例如用协议头伪装的「心跳电文」），模块只负责节拍发送与状态机。

---

## 2. 原则

| 原则 | 说明 |
|------|------|
| 策略可开关 | 心跳、wait-ack 等均可独立 enable |
| 帧内容外置 | 心跳发送内容、（若需要）本地构造的应答模板均由调用方注入或回调提供 |
| 识别可配置 | 如何从收包判定 A/N/H，用可配置规则或回调，避免写死 `9999999999` / `msgType` 偏移 |
| 组报不进模块 | 不解析业务体；只处理「整帧字节 + 策略」 |

---

## 3. 建议配置项（草案）

名称可在实现时调整，语义如下。

### 3.1 链路基础（始终可用）

| 参数 | 含义 |
|------|------|
| `host` / `port` | 远端 |
| `autoReconnect` | 是否自动重连 |
| `reconnectIntervalMs` | 重连间隔 |
| `connectTimeoutMs` | 连接超时（若实现） |

### 3.2 心跳（可选）

| 参数 | 含义 |
|------|------|
| `heartbeatEnabled` | 是否启用心跳 |
| `heartbeatIntervalMs` | 发送周期 |
| `heartbeatFrame` | 要发送的完整帧（`QByteArray`）；或 |
| `heartbeatFrameProvider` | 每次触发时回调取帧（便于动态改内容） |
| `heartbeatExpectReply` | 是否期待对端回心跳（默认 `false`，对齐旧规则「心跳不应答」） |

**兼容点：** 调用方用 GMAM 组一帧「H + 约定电文号 + 0x0A」赋给 `heartbeatFrame`，即与旧 PES 心跳电文兼容；换协议只需换帧内容，不必改 TCP 模块。

### 3.3 正负应答 / 发送窗口（可选）

| 参数 | 含义 |
|------|------|
| `ackEnabled` | 是否启用「发数据后等待应答」 |
| `ackTimeoutMs` | 超时未应答则重发 |
| `ackMaxRetry` | 最大重发次数，超限丢弃并通知 |
| `ackPositiveMatcher` | 如何判定正应答（回调或简单规则） |
| `ackNegativeMatcher` | 如何判定负应答 |
| （可选）`onAckPositive` / `onAckNegative` | 额外钩子 |

**匹配器输入：** 已拆出的一帧 `QByteArray`（或原始缓冲切片）。  
**旧协议示例：** 帧长 23 且某偏移为 `'A'`/`'N'`，且电文号不含心跳哨兵——该逻辑放在**应用提供的 matcher** 或可选的「PES 预设配置」，而不是写死在核心里。

未启用 `ackEnabled` 时：队列只负责尽快发，不等待 A/N（通用透传模式）。

### 3.4 接收拆帧（可选，建议与应答联动）

| 参数 | 含义 |
|------|------|
| `frameMode` | `Raw`（整段 `readAll` 上抛）/ `LengthPrefix` / `CustomSplitter` |
| 长度前缀规则 | 如：前 6 字节十进制总长、结尾 `0x0A`（PES 可作一种预设） |

P0 可先 `Raw`；启用 ack 时再要求拆帧或 CustomSplitter。

---

## 4. 行为示意

```text
enqueue(业务帧) ──► 发送队列
                      │
        ackEnabled? ──┤── no ──► 发出即出队（或发完出队）
                      │
                      └── yes ─► 发出后等待 matcher(A/N)
                                   ├─ A → 出队，发下一条
                                   ├─ N → 丢弃，报错通知
                                   └─ 超时 → 重发，超次丢弃

heartbeatEnabled? ──► 定时取 heartbeatFrame / provider → 直接发送
                      （默认不占用 ack 窗口、不期待应答）
```

---

## 5. 与旧项目映射

| 旧行为 | 配置化后 |
|--------|----------|
| 每 5s 发 `MsgHeartNew` | `heartbeatEnabled=true`，`heartbeatFrame=GMAM组好的心跳电文` |
| 注释中的 A/N 规则 | `ackEnabled=true` + matcher 判 `'A'`/`'N'` |
| 无应答策略的透传 | 两开关均 `false` |
| 写死电文号 `9999999999` | 放入注入帧 / matcher，不进核心常量 |

## 6. 模块边界（再次确认）

| 在 module_tcp | 不在 module_tcp |
|---------------|-----------------|
| 开关与定时、队列、重连、可选拆帧 | 字段级组报（GMAM） |
| 发送注入的心跳/业务帧 | 业务含义（换辊、磨削…） |
| 调用 matcher 驱动状态机 | 强制绑定某一厂头格式（仅可提供可选预设） |
