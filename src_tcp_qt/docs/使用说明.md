# module_tcp 使用说明

TCP **客户端**：收发已组好的 `QByteArray`。组报不在本模块。

依赖：`QT += core network`，C++17。

---

## 1. 接入

```pro
include($$PWD/相对路径/module_tcp/module_tcp.pri)
```

```cpp
#include "TcpClient.h"
#include "TcpClientConfig.h"
// 可选：#include "PesFrameHints.h"
```

---

## 2. 最小示例

```cpp
TcpClientConfig cfg = TcpClientConfig::defaults();
cfg.host = QStringLiteral("127.0.0.1");
cfg.port = 9000;

TcpClient client;
client.setConfig(cfg);

QObject::connect(&client, &TcpClient::connected, [&]() {
    client.enqueue(QByteArray("hello"));
});
QObject::connect(&client, &TcpClient::frameReceived, [](const QByteArray& f) {
    qDebug() << f;
});

client.connectToHost();
```

开 wait-ack 时：**先** `setAckMatchers`，**再** `setConfig` / `connectToHost`。

```cpp
client.setAckMatchers(
    [](const QByteArray& f) { return f.contains('A'); },  // 正应答
    [](const QByteArray& f) { return f.contains('N'); }   // 负应答
);
cfg.ackEnabled = true;
client.setConfig(cfg);
```

## 3. TcpClient API

### 3.1 方法与参数

#### `void setConfig(const TcpClientConfig& config)`

| 参数 | 类型 | 意义 |
|------|------|------|
| `config` | `TcpClientConfig` | 整份运行配置（地址、队列、心跳开关、ack、拆帧等）。字段见 §4。已连接时也会下发到工作线程。 |

#### `TcpClientConfig config() const`

无参数。返回当前门面侧保存的配置副本。

#### `void connectToHost()` / `void disconnectFromHost()`

无参数。前者按当前配置连接（必要时启动工作线程）；后者主动断开。

#### `bool isConnected() const`

无参数。`true`＝套接字已连接。

#### `bool enqueue(const QByteArray& frame)`

| 参数 / 返回 | 类型 | 意义 |
|-------------|------|------|
| `frame` | `QByteArray` | 要发送的**完整帧字节**（模块不组报，原样入队写出） |
| 返回值 | `bool` | `true` 已入队；`false`＝空帧，或队列满且策略为 `Reject`，或未开队列且当前未连接 |

#### `void setHeartbeatFrame(const QByteArray& frame)`

| 参数 | 类型 | 意义 |
|------|------|------|
| `frame` | `QByteArray` | 固定心跳整帧内容。需同时 `heartbeatEnabled=true` 才会周期发送。与 provider 同时存在时 **provider 优先**。 |

#### `void setHeartbeatFrameProvider(TcpHeartbeatFrameProvider provider)`

| 参数 | 类型 | 意义 |
|------|------|------|
| `provider` | `std::function<QByteArray()>` | 每次心跳定时器触发时调用，返回本拍要发的心跳帧；返回空则本拍不发。 |

#### `void setAckMatchers(TcpFrameMatcher positive, TcpFrameMatcher negative, TcpFrameMatcher heartbeatIgnore = {})`

| 参数 | 类型 | 意义 |
|------|------|------|
| `positive` | `TcpFrameMatcher` | 收到一帧时：返回 `true`＝**正应答** → `sendAccepted`，当前发送帧出队 |
| `negative` | `TcpFrameMatcher` | 返回 `true`＝**负应答** → `sendRejected`，当前发送帧丢弃 |
| `heartbeatIgnore` | `TcpFrameMatcher` | 可选。返回 `true`＝本帧当对端心跳等，**不驱动** ack（先于 A/N 判断） |

`TcpFrameMatcher` = `std::function<bool(const QByteArray& frame)>`，入参是拆好的完整帧。  
`ackEnabled=true` 时 **必须** 提供有效的 `positive` / `negative`，否则配置会被关掉并报错。详见 §6。

#### `void setCustomFrameSplitter(TcpCustomFrameSplitter splitter)`

| 参数 | 类型 | 意义 |
|------|------|------|
| `splitter` | `TcpCustomFrameSplitter` | 自定义拆帧函数。仅当 `frameMode == Custom` 时使用。签名与约定见 §5。 |

#### `void clearReceiveBuffer()`

无参数。清空接收侧拆帧内部缓冲与最近拆帧错误（**异步**投递到 worker，返回不代表已清空）。  
**不影响**发送队列、wait-ack、连接状态。  
若 `ackEnabled`：可能丢掉尚未匹配的应答 → 随后可能超时重传（预期副作用）。详见 §8。

#### `int receiveBufferSize() const`

无参数。返回拆帧缓冲未消费字节数的**跨线程快照**，**仅诊断**；勿作强一致业务条件。worker 未启动时为 `0`。

---

### 3.2 信号与参数

| 信号 | 参数 | 意义 |
|------|------|------|
| `connected()` | — | 连接成功 |
| `disconnected()` | — | 连接断开 |
| `errorOccurred(message)` | `QString message` | 错误说明（超时、套接字错误、拆帧超长、ack 未配 matcher 等） |
| `bytesReceived(data)` | `QByteArray data` | 本轮 socket `readAll` 的原始字节（可能粘包/半包） |
| `frameReceived(frame)` | `QByteArray frame` | 按拆帧规则得到的**完整帧**（业务优先用这个） |
| `queueRejected()` | — | `enqueue` 因队列满（Reject）未入队 |
| `queueHighWater()` | — | 队列长度达到/超过 `highWaterMark`（边沿一次） |
| `queueLowWater()` | — | 曾过高水位后回落到 `lowWaterMark` 及以下 |
| `sendAccepted()` | — | wait-ack：正应答匹配，当前发送帧已确认 |
| `sendRejected(reason)` | `QString reason` | wait-ack：负应答或超时达 `ackMaxRetry`；`reason` 为原因文案 |

## 4. 配置参数（`TcpClientConfig`）

`defaults()` 即下表默认。matcher / provider **不进**本结构，用上面的 setter。

### 连接

| 参数 | 默认 | 作用 |
|------|------|------|
| `host` | `127.0.0.1` | 远端地址 |
| `port` | `9000` | 远端端口 |
| `autoReconnect` | `true` | 断线后是否自动重连 |
| `reconnectIntervalMs` | `3000` | 重连间隔 |
| `connectTimeoutMs` | `3000` | 单次连接超时 |

### 发送队列

| 参数 | 默认 | 作用 |
|------|------|------|
| `sendQueueEnabled` | `true` | 是否走队列 |
| `sendQueueMaxSize` | `100` | 队列上限 |
| `sendQueueOverflowPolicy` | `Reject` | `Reject` 拒收 / `DropOldest` 丢最旧再入队 |
| `sendIntervalMs` | `0` | 两帧最小间隔；`0` 不限速 |
| `highWaterMark` | `100` | 达此发高水位信号 |
| `lowWaterMark` | `50` | 回落发低水位信号 |

### 心跳

| 参数 | 默认 | 作用 |
|------|------|------|
| `heartbeatEnabled` | `false` | 是否周期发心跳 |
| `heartbeatIntervalMs` | `5000` | 周期 |
| `heartbeatFrame` | 空 | 固定心跳内容；也可用 `setHeartbeatFrame` |
| `heartbeatOccupyAckWindow` | `false` | `false`：心跳旁路，不占 wait-ack |

### wait-ack

| 参数 | 默认 | 作用 |
|------|------|------|
| `ackEnabled` | `false` | 是否等应答再发下一帧 |
| `ackTimeoutMs` | `2000` | 超时重发 |
| `ackMaxRetry` | `5` | **含首次**的最大发送次数 |
| `ackWindow` | `1` | 同时未确认帧数（当前按 1 停等） |

`ackEnabled=true` 但未设 A/N matcher → 自动关 ack 并报错。

### 拆帧

| 参数 | 默认 | 作用 |
|------|------|------|
| `frameMode` | `Raw` | 见下一节 |
| `lengthPrefixOffset` | `0` | 长度字段起点 |
| `lengthPrefixSize` | `6` | 长度字段字节数 |
| `lengthPrefixEncoding` | `DecimalAscii` | 十进制 ASCII / 大端 / 小端 |
| `lengthIncludesHeader` | `true` | `true`：长度=整帧；`false`：长度=体长再加头等 |
| `hasFrameTerminator` | `true` | 是否校验末字节 |
| `frameTerminator` | `0x0A` | 结束符 |
| `maxFrameSize` | `8192` | 超长则丢缓冲并报错 |

## 5. 拆帧模式

| `frameMode` | 作用 |
|-------------|------|
| `Raw` | 每次读到的块即一帧（粘包不拼、半包也不攒） |
| `LengthPrefix` | 按长度前缀从内部缓冲拼完整帧 |
| `PesAscii` | 6 位十进制总长 + 尾 `0x0A`（内部按 LengthPrefix 处理） |
| `Custom` | 模块只攒缓冲，**怎么切帧由你提供的函数决定** |

### Custom 怎么理解

TCP 是流：一次 `read` 可能半包、粘多包。`Raw` 不管；`LengthPrefix`/`PesAscii` 用固定规则切。  
若协议是别的规则（如定界符 `0x0D0A`、特殊头尾、变长且长度算法自定义），设：

1. `cfg.frameMode = TcpFrameMode::Custom`
2. `setCustomFrameSplitter(fn)`

回调类型（`IFrameMatcher.h`）：

```cpp
using TcpCustomFrameSplitter =
    std::function<QVector<QByteArray>(QByteArray& buffer)>;
```

| 约定 | 说明 |
|------|------|
| 入参 `buffer` | 模块已把新读到的字节 **append** 进去；你就地改它 |
| 返回值 | 本轮能切出的完整帧列表（可空、可多帧） |
| 你必须做的 | 从 `buffer` **删掉已消费字节**；半包留下等下次再调 |
| 未设 splitter | Custom 下不会出帧（返回空） |

例：按换行 `\n` 切（半行留在 buffer）：

```cpp
client.setCustomFrameSplitter([](QByteArray& buf) {
    QVector<QByteArray> out;
    for (;;) {
        const int i = buf.indexOf('\n');
        if (i < 0)
            break;
        out.push_back(buf.left(i + 1)); // 含 '\n'
        buf.remove(0, i + 1);
    }
    return out;
});

TcpClientConfig cfg = TcpClientConfig::defaults();
cfg.frameMode = TcpFrameMode::Custom;
client.setConfig(cfg);
```

切出的每一帧仍走 `frameReceived`，也可再交给 ack matcher。

## 6. Matcher 是干什么的

模块**不解析业务含义**，只把收到的「完整帧」交给你给的函数判断：

| 回调 | 作用 |
|------|------|
| 正应答 matcher | 返回 `true` → 当前发送成功（`sendAccepted`，出队） |
| 负应答 matcher | 返回 `true` → 当前发送失败（`sendRejected`，丢弃） |
| 心跳忽略 matcher（可选） | 返回 `true` → 本帧不参与 ack（例如对端心跳） |

类型：`TcpFrameMatcher = std::function<bool(const QByteArray&)>`（见 `IFrameMatcher.h`）。

可选 PES 预设（`PesFrameHints.h`）：

| 函数 | 作用 |
|------|------|
| `matcherPositiveA()` | 偏移 21 为 `'A'` |
| `matcherNegativeN()` | 偏移 21 为 `'N'` |
| `matcherHeartbeatIgnore()` | 电文号区像全 `9` 则忽略 |
| `applyPesFramingHints(cfg)` | 填 PesAscii 拆帧相关字段 |
| `recommendedRuntimeFlags(cfg)` | 上项 + 打开心跳/ack 常用开关 |

```cpp
cfg = tcp_pes::recommendedRuntimeFlags(cfg);
client.setAckMatchers(tcp_pes::matcherPositiveA(),
                      tcp_pes::matcherNegativeN(),
                      tcp_pes::matcherHeartbeatIgnore());
client.setHeartbeatFrame(/* 已组好的心跳帧 */);
```

---

## 7. 注意

- 空帧 `enqueue` 返回 `false`。
- 业务收包优先 `frameReceived`；`bytesReceived` 是原始粘包块。
- 需要两条链路时建两个 `TcpClient`，由外部决定谁发谁收。

## 8. 帧失步与上层重同步

**正常半包**：缓冲头部是合法帧起点，只是字节不够 → LengthPrefix 会等待，这是正确行为。  
**帧失步**：缓冲头部是残片 → 模块**无**协议级可靠 Resync（仅有非法长度滑 1 字节、超长清空等弱处理；勿当工业可用重同步）。

可靠重同步由**上层**负责。模块提供：

| 手段 | 用法 |
|------|------|
| `Custom` + `setCustomFrameSplitter` | 推荐：在 splitter 内校验、滑动、删已消费字节 |
| `Raw` + `bytesReceived` | 上层自建缓冲与重同步 |
| `clearReceiveBuffer()` | LengthPrefix/PesAscii 下业务校验失败时清空模块缓冲止损 |
| `receiveBufferSize()` | 诊断未对齐字节数（快照） |

**断开 / 重连与缓冲：**

- `disconnected` 时模块**不会**自动清空接收缓冲；断开后若长时间不重连、也不手动 clear，旧残片会留在内部缓冲里。  
- **建议**：上层在 `disconnected`（或主动断开后）调用一次 `clearReceiveBuffer()`。  
- 何时模块会清缓冲（勿与「任意调用 connect 都会清」混淆）：  
  - 主动 `connectToHost()`：在**发起新一轮连接尝试前**会 clear（已是 Connected/Connecting 则直接返回，**本次不清**）；连接**成功**时会再 clear 一次。  
  - **自动重连**：发起前**不清**；仅连接**成功**时 clear。

```cpp
QObject::connect(&client, &TcpClient::disconnected, &client, [&]() {
    client.clearReceiveBuffer(); // 建议：断开时手动清理
});
```

`frameReceived` 只表示**语法上拆出完整帧**，不等于业务合法；业务须自校验。  
不建议「单帧失败就 clear」；可用连续失败计数，达 N 次再盲重置。

```cpp
int bad = 0;
QObject::connect(&client, &TcpClient::frameReceived, &client, [&](const QByteArray& f) {
    if (!businessFrameOk(f)) {
        if (++bad >= 3) { // 示例：连续失败再止损，阈值按业务定
            client.clearReceiveBuffer();
            bad = 0;
        }
        return;
    }
    bad = 0;
    handleFrame(f);
});
```
