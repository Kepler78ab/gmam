# v0.0.2 — 注释规范（古法编程可读）

## 1. 目标

在 `module_tcp` 头文件（及必要时 `.cpp` 关键逻辑）补全 **Doxygen 风格** 说明，使人在 Qt Creator / VS / Cursor 里：

- 悬停方法即可看到「干什么、参数什么意思、返回什么」；
- 打开头文件即可当简版 API 手册读；
- 与 `docs/使用说明.md` 语义一致，注释更短、贴代码。

**不改**运行逻辑、信号语义、默认值、对外 API 签名（本版零行为变更）。

---

## 2. 写哪些

### 2.1 必须（对外 / 可被调用方看到）

| 文件 | 内容 |
|------|------|
| `TcpClient.h` | 类 `@brief`；每个 public 方法：`@brief` / `@param` / `@return`；signals 每个槽参数含义一行 |
| `TcpClientConfig.h` | 结构 `@brief`；各字段行尾或分组块注释（与设计_03 / 使用说明对齐） |
| `TcpTypes.h` | 枚举 `@brief`；每个枚举值一行含义 |
| `IFrameMatcher.h` | `TcpFrameMatcher` / `TcpCustomFrameSplitter` 类型别名说明（入参、返回、约定） |
| `profiles/PesFrameHints.h` | namespace 说明；各 inline 函数 `@brief` + 关键约定（偏移等） |

### 2.2 建议（模块内部，便于维护）

| 文件 | 内容 |
|------|------|
| `TcpClientWorker.h` | 类职责；public slots / signals 一句；关键 private 状态机成员可分组注释 |
| `SendQueue.h` | 类 + 各方法 `@brief` / `@return` |
| `FrameAssembler.h` | 类 + `feed` / `setConfig` 等 |

Worker / Assembler 的 `.cpp`：**仅**对非显而易见的状态机段落加短块注释（ack 停等、心跳旁路、PesAscii 转 LengthPrefix），不要求每个函数重复头文件已有说明。

### 2.3 明确不做

- 不写进 `tcp_ui_test` / `tcp_peer_test` / `md_tcp` 冒烟（非 module 交付面）。
- 不把 `使用说明.md` 大段贴进注释。
- 不新增英文-only 与中文混排两套；**统一中文**（标识符仍英文）。
- 不借机重构 API / 改名。

## 3. 写法约定

```cpp
/**
 * @brief 入队发送一整帧。
 * @param frame 已组好的完整帧；空帧不会入队。
 * @return true 已入队；false 空帧、或 Reject 策略下队列已满、或未开队列且未连接。
 */
bool enqueue(const QByteArray& frame);
```

| 标签 | 用法 |
|------|------|
| `@file` | 头文件顶部可保留一行文件职责 |
| `@brief` | 一句话；不要写实现细节流水账 |
| `@param` | 每个参数：名称 + 意义（含单位/空值约定） |
| `@return` | 有返回值必写；`bool` 写清 true/false |
| `@note` | 仅关键约束（如「ackEnabled 前须 setAckMatchers」） |
| 枚举值 | `///< 含义` 行尾注释即可 |

信号示例：

```cpp
/** 拆出的完整帧（业务优先使用）。 */
void frameReceived(const QByteArray& frame);
```

| 载体 | 角色 |
