# 通用报文组装方案

## 1\. 背景与目标

### 1\.1 背景

在设备通信场景中，需要根据一份“字段描述表”（schema）动态地把外部传入的值组装成符合协议要求的二进制/ASCII 报文。不同设备、不同协议的字段定义不同，如果为每种报文单独写死拼接代码，维护成本高、易出错。

因此需要一个**通用报文组装器**：用 schema 驱动组装过程，schema 描述字段的名称、类型、长度、精度等信息，外部只需提供“字段名 \-\> 值”的映射即可完成组装。

### 1\.2 目标

- 通用：同一套组装器支持多种报文，只需替换 schema。

- 分层：数据内容组装与外部报文封装解耦。

- 可控：失败时返回空结果，并通过引用带出错误原因，便于调用方判断。

- 可扩展：后续新增字段类型、新增精度策略时，改动局部化。

## 2\. 需求说明

### 2\.1 报文整体结构

外层电文由三部分组成：

|部分|长度|说明|
|---|---|---|
|电文头部|29 字节|固定结构，由外部负责组装|
|数据内容|最大 8162 字节|**本方案组装器负责的部分**|
|结束符|1 字节|固定为 `0x0A`|

组装器**只负责“数据内容”这一段**，电文头部和结束符由调用方拼装。
最终报文形如：

```Plaintext
[29字节电文头] + [数据内容] + [0x0A]
```

### 2\.2 数据内容编码规则

1. 传输数据全部使用 **ASCII 码**表示。

2. 数值型数据用数字字符表示。

3. **数值型（N）**：采用**右对齐**，不足位数**左侧补 ****`'0'`**。
例：5 位数值型，`123` 表示为 `"00123"`。

4. **字符型（C）**：采用**左对齐**，不足位数**右侧补空格**。
例：5 位字符型，`"z01"` 表示为 `"z01 "`。

5. **预留数据**：全部填**空格**。

6. **无法采集的数据**：

    - 数值型填 `'0'`（即数值 0）

    - 字符型填**空格**

7. **溢出 / 超额**（编码后长度 \> `length`）：按字段配置的 **`OverflowPolicy`** 处理。

    |策略|含义|典型用途|
    |---|---|---|
    |`Error`|报错并记入错误列表（**结构体默认，P0**）|严格模式；忘记配置时的行为|
    |`FillChar`|整字段填 `overflowFill`（常用 `'9'`）|协议规则 7：数值溢出填 9|
    |`Truncate`|按 **resolve 后的对齐方向** 截断|兼容旧 memcpy；左对齐截左、右对齐截右|

    - **Numeric + `FillChar`**：例 length=5，溢出 → `"99999"`。
    - **Truncate**：跟随 `FieldAlign`（`ByType` 时 N 右截、C 左截）。
    - 直写 schema 时 Numeric 若需填 9，须显式写 `FillChar`；或用 `makeNumericField`（工厂默认 FillChar）。

    > `Rounding::Truncate`（小数位截断）与 `OverflowPolicy::Truncate`（超额截断）层级不同，勿混淆。

### 2\.2\.1 对齐与填充（v0.0.3）

默认对齐：Numeric 右对齐补 `'0'`，Chars 左对齐补空格（规则 3、4）。  
可通过 `FieldAlign` / `padFill` / `missingFill` / `MissingPolicy` 覆盖；`padFill`/`missingFill` 为 `'\0'` 时按类型取默认。详见 `docs/v0.0.3/对齐与填充策略设计.md` 与 `docs/使用说明.md`。

### 2\.3 数值型精度（scale）

数值型字段支持配置**小数点位置**，用 `scale` 表示 `10^-scale`：

- `scale = 0`：整数，`53` → `"53"`

- `scale = 3`：`53.167` → `"53167"`（内部存储值 = 真实值 × 10³）

- `scale = 3`：`56.7877` → `"56787"`（按截断策略）

小数点位置**逐字段可配**，默认 `0`。
小数位处理支持两种策略：

- **截断（Truncate）**：直接丢弃多余小数位。

- **四舍五入（Round）**：看截断位后一位，≥5 则进位。

### 2\.4 输入与输出约定

- **输入值统一为字符串**：由调用方负责把业务数据转成字符串，组装器不做数值类型推断。
这样可避免浮点精度歧义。

- **输入形式**：`QHash<QString, QString>`，键为字段名，值为字符串。

- **输出**：成功返回 `QByteArray`（数据内容）；失败返回**空 ****`QByteArray`**，
并通过 `QStringList& errors` 带出全部错误（v0.0.2，见 §13）。

### 2\.5 字段类型

数据内容中字段分为三类：

|类型|枚举|默认对齐/补位|overflow 结构体默认|
|---|---|---|---|
|数值型|`Numeric`|右对齐左补 `'0'`，支持 scale|`Error`（P0）；协议填 9 请写 `FillChar`|
|字符型|`Chars`|左对齐右补空格|`Error`（可改 `Truncate`）|
|预留|`Reserved`|全部填空格|—|

### 2\.6 异常与边界处理

|场景|处理|
|---|---|
|数值型输入含非法字符/负数/空（非缺值路径）|记入 errors，失败占位后继续|
|数值型位数 \> length|按 `OverflowPolicy`|
|字符型超长|按 `OverflowPolicy`；Truncate 跟 align|
|字段缺值|按 `MissingPolicy` + `missingFill`（默认 N→0 / C→空格）|
|Reserved 字段|忽略传入值，直接填空格|
|字段 length ≤ 0|记入 errors，跳过|
|有任意字段级/整体级错误|返回空 QByteArray，errors 非空|

### 2\.7 内层 data 报文最终形态（旧 T9 举例）

## 3\. 总体设计

### 3\.1 分层结构

```Plaintext
┌──────────────────────────────────────────────────┐
│  外层电文组装（调用方负责）                          │
│  ┌───────────────┬────────────────────┬─────────┐ │
│  │ 电文头 29字节   │  数据内容 ≤8162字节  │ 0x0A    │ │
│  └───────────────┴────────────────────┴─────────┘ │
│                          ↑                        │
│                 DataContentBuilder                │
│                 （本方案负责）                      │
└──────────────────────────────────────────────────┘
```

- **第一层：数据内容组装** —— 由本方案 `DataContentBuilder` 完成。

- **第二层：外部头尾拼装** —— 由调用方完成，格式为 `head + data + 0x0A`。

### 3\.2 核心概念

- **Schema（字段描述表）**：`QVector<FieldDetail>`，顺序即拼接顺序。

- **FieldDetail（字段描述）**：`{name, type, length, scale, rounding}`。

- **Builder（组装器）**：持有 schema，接收值映射，输出数据内容。

### 3\.3 组装流程

```Plaintext
输入: QHash<QString, QString> values + Schema
  │
  ├─ 遍历 schema 中每个字段
  │    │
  │    ├─ Reserved? ──→ 填空格
  │    │
  │    ├─ 从 values 取值
  │    │    ├─ 未传? ──→ 按类型填默认（0 或空格）
  │    │    └─ 已传? ──→ 调用 encodeField
  │    │
  │    └─ encodeField 按类型编码
  │         ├─ Numeric: 解析字符串 → 放大 → 补位 → 溢出处理
  │         ├─ Chars:   Latin1 → 补空格
  │         └─ 出错 → 返回空 + error
  │
  └─ 全部成功 → 返回拼接好的 QByteArray
```

### 3\.4 类图（简化）

```Plaintext
┌─────────────────────┐
│    FieldDetail      │
│─────────────────────│
│ name     : QString  │
│ type     : FieldType│
│ length   : int      │
│ scale    : int      │
│ rounding : Rounding │
└─────────────────────┘
            △
            │ 包含
┌─────────────────────────┐

```

## 4\. 数据结构定义

### 4\.1 枚举

```C++
// 字段类型
enum class FieldType {
    Numeric,    // 数值型 N
    Chars,      // 字符型 C
    Reserved,   // 预留，填空格
};
// 小数处理方式（仅 Numeric 用；与 OverflowPolicy::Truncate 无关）
enum class Rounding {
    Truncate,   // 小数位截断（默认）
    Round,      // 四舍五入
};
// 超额策略（编码后长度 > length；规则 7 可配）
enum class OverflowPolicy {
    Error,      // 超长 → 返回空 + error
    Truncate,   // 超长 → 按类型对齐方向截断（兼容旧 memcpy）
    FillChar,   // 超长 → 整字段填 overflowFill（Numeric 协议默认 '9'）
};
```

### 4\.2 字段描述

```C++
struct FieldDetail {
    QString   name;
    FieldType type     = FieldType::Reserved;
    int       length   = 0;
    int       scale    = 0;
    Rounding  rounding = Rounding::Truncate;
    OverflowPolicy overflow = OverflowPolicy::Error;  // P0：默认 Error
    char      overflowFill = '9';
    FieldAlign     align         = FieldAlign::ByType;       // v0.0.3
    char           padFill       = '\0';                   // '\0' = 按类型
    char           missingFill   = '\0';
    MissingPolicy  missingPolicy = MissingPolicy::TreatAsMissing;
};
```

**推荐**：Numeric 协议填 9 时显式 `FillChar`，或使用 `makeNumericField`。  
对齐/缺值详见 v0.0.3；错误收集见 §13 / v0.0.2。调用说明：`docs/使用说明.md`。

### 4\.3 组装器接口

```C++
    QVector<FieldDetail> m_schema;
    int m_totalLength = 0;
};
```

## 5\. 核心实现

### 5\.1 数值字符串解析（避开浮点误差）

数值型不直接用浮点乘，而是**按字符串解析**，从根本上避免 IEEE754 精度问题
（例如 `0.29 * 100 = 28.999...` 这类误差）。

解析逻辑：

1. 去空白；空串报错。

2. 检测负号 → 报错（协议不支持负数）。

3. 拆分整数部分 / 小数部分。

4. 校验两部分均为数字字符，否则报错。

5. 按 `scale` 处理小数：

    - 小数位 ≥ scale：取前 scale 位；若为四舍五入且下一位 ≥5，则整体 \+1。

    - 小数位 \< scale：右侧补 `'0'`。

6. 拼成纯数字串，去前导 0（至少保留一位）。

```C++
static bool parseNumericString(const QString& input,
                               int scale,
                               Rounding rounding,
                               QString& digitsStr,
                               QString& error,
                               const QString& fieldName);
```

### 5\.2 单字段编码

按类型分派：

- `Numeric`：调用 `parseNumericString` → 超额处理（`OverflowPolicy`）→ 右对齐左补 `'0'`。

- `Chars`：转 Latin1 → 超额处理 → 右补空格。

- `Reserved`：直接填空格。

**超额处理**（`digitsStr.size()` 或 `raw.size()` \> `length` 时）：

|`overflow`|Numeric|Chars|
|---|---|---|
|`FillChar`|整字段填 `overflowFill`（默认 `'9'`）|整字段填 `overflowFill`|
|`Truncate`|保留右侧 `length` 位数字，再左补 `'0'`|保留左侧 `length` 字节，再右补空格|
|`Error`|返回空 \+ error|返回空 \+ error|

```C++
static bool encodeField(const QString& value,
                        const FieldDetail& f,
                        QByteArray& out,
                        QString& error);
```

### 5\.3 整体组装

```C++
QByteArray DataContentBuilder::build(
        const QHash<QString, QString>& values,
        QString& error) const;
```

流程：

1. 清空 error。

2. 预留 `m_totalLength` 空间。

3. 遍历 schema：

    - Reserved → 填空格。

    - 从 values 取值；未传 → 按类型填默认值。

    - 调用 `encodeField`；失败 → 返回空。

4. 返回拼接结果。

## 6\. 完整代码

### 6\.1 `DataContentBuilder.h`

```C++
#pragma once
#include <QByteArray>
#include <QHash>
#include <QString>
#include <QVariant>
#include <QVector>
// 字段类型
enum class FieldType {
    Numeric,    // 数值型 N
    Chars,      // 字符型 C
    Reserved,   // 预留，填空格
};
// 小数处理方式（仅 Numeric 用）
enum class Rounding {
    Truncate,   // 小数位截断（默认）
    Round,      // 四舍五入
};
// 超额策略（编码后长度 > length）
enum class OverflowPolicy {
    Error,      // 超长 → 返回空 + error
    Truncate,   // 超长 → 按类型对齐方向截断
    FillChar,   // 超长 → 整字段填 overflowFill
};
// 单个字段描述

    QString   name;
    FieldType type     = FieldType::Reserved;

    int       scale    = 0;                    // 10^-scale，仅 Numeric 用

    OverflowPolicy overflow = OverflowPolicy::Error;
    char      overflowFill = '9';             // 仅 FillChar 时使用
};
// 数据内容组装器
class DataContentBuilder {
public:
    explicit DataContentBuilder(QVector<FieldDetail> schema);
    // 成功返回数据内容；失败返回空 QByteArray，error 带原因

                     QString& error) const;
    // 数据内容总长度（所有字段 length 之和）
    int totalLength() const { return m_totalLength; }
private:
    QVector<FieldDetail> m_schema;
    int m_totalLength = 0;
};
```

### 6\.2 `DataContentBuilder.cpp`

```C++
#include "DataContentBuilder.h"
// ---------------------------------------------------------
// 把输入字符串按 scale 解析成纯数字串（不含小数点、不含符号）
// 返回 false 表示非法输入，error 写入原因
// ---------------------------------------------------------
static bool parseNumericString(const QString& input,
                               int scale,
                               Rounding rounding,
                               QString& digitsStr,
                               QString& error,
                               const QString& fieldName)
{
    digitsStr.clear();
    QString s = input.trimmed();
    if (s.isEmpty()) {
        error = QString("字段 %1 数值为空").arg(fieldName);
        return false;
    }
    // 负数不支持
    if (s.startsWith('-')) {
        error = QString("字段 %1 不支持负数").arg(fieldName);
        return false;
    }
    if (s.startsWith('+'))
        s.remove(0, 1);
    // 拆整数 / 小数部分
    const int dotPos = s.indexOf('.');
    QString intPart  = (dotPos < 0) ? s : s.left(dotPos);
    QString fracPart = (dotPos < 0) ? QString() : s.mid(dotPos + 1);
    if (intPart.isEmpty())
        intPart = "0";
    // 字符校验
    for (const QChar c : intPart) {
        if (!c.isDigit()) {
            error = QString("字段 %1 含非法字符").arg(fieldName);
            return false;
        }
    }
    for (const QChar c : fracPart) {
        if (!c.isDigit()) {
            error = QString("字段 %1 含非法字符").arg(fieldName);
            return false;
        }
    }
    // 处理小数部分
    QString scaledFrac;
    if (fracPart.size() >= scale) {
        scaledFrac = fracPart.left(scale);
        // 四舍五入：看截断位后一位
        if (rounding == Rounding::Round &&
            scale < fracPart.size() &&
            fracPart[scale] >= '5') {
            // 整数部分 + 已保留小数部分，整体 +1
            QString whole = intPart + scaledFrac;
            int i = whole.size() - 1;
            while (i >= 0) {
                if (whole[i] < '9') {
                    whole[i] = QChar(whole[i].unicode() + 1);
                    break;
                }
                whole[i] = '0';
                --i;
            }
            if (i < 0)
                whole.prepend('1');   // 全 9 进位
            // 若进位导致位数超过 length，保留原样交给溢出处理
            digitsStr = whole;
            return true;
        }
    } else {
        // 小数位不足，右侧补 0
        scaledFrac = fracPart;
        scaledFrac.append(QString(scale - fracPart.size(), '0'));
    }
    digitsStr = intPart + scaledFrac;
    // 去前导 0（至少保留一位）
    while (digitsStr.size() > 1 && digitsStr[0] == '0')
        digitsStr.remove(0, 1);
    return true;
}
// ---------------------------------------------------------
// 单字段编码
// ---------------------------------------------------------
static bool encodeField(const QString& value,
                        const FieldDetail& f,
                        QByteArray& out,
                        QString& error)
{
    out.clear();
    if (f.length <= 0) {
        error = QString("字段 %1 长度非法").arg(f.name);
        return false;
    }
    switch (f.type) {
    case FieldType::Numeric: {
        QString digitsStr;
        if (!parseNumericString(value, f.scale, f.rounding,
                                digitsStr, error, f.name))
            return false;
        // 超额：按 OverflowPolicy
        if (digitsStr.size() > f.length) {
            switch (f.overflow) {
            case OverflowPolicy::FillChar:
                out = QByteArray(f.length, f.overflowFill);
                return true;
            case OverflowPolicy::Truncate:
                digitsStr = digitsStr.right(f.length);
                break;
            case OverflowPolicy::Error:
                error = QString("字段 %1 数值溢出").arg(f.name);
                return false;
            }
        }
        // 右对齐左补 '0'
        out = QByteArray(f.length - digitsStr.size(), '0')
              + digitsStr.toLatin1();
        return true;
    }
    case FieldType::Chars: {
        QByteArray raw = value.toLatin1();
        if (raw.size() > f.length) {
            switch (f.overflow) {
            case OverflowPolicy::FillChar:
                out = QByteArray(f.length, f.overflowFill);
                return true;
            case OverflowPolicy::Truncate:
                raw = raw.left(f.length);
                break;
            case OverflowPolicy::Error:
                error = QString("字段 %1 字符超长").arg(f.name);
                return false;
            }
        }
        out = raw;
        out.append(f.length - raw.size(), ' ');
        return true;
    }
    case FieldType::Reserved: {
        out = QByteArray(f.length, ' ');
        return true;
    }
    }
    error = "未知字段类型";
    return false;
}
// ---------------------------------------------------------
// 构造 / 组装
// ---------------------------------------------------------
DataContentBuilder::DataContentBuilder(QVector<FieldDetail> schema)
    : m_schema(std::move(schema))
{
    for (const auto& f : m_schema) {
        if (f.length > 0)
            m_totalLength += f.length;
    }
}
QByteArray DataContentBuilder::build(
        const QHash<QString, QString>& values,
        QString& error) const
{
    error.clear();
    QByteArray buffer;
    buffer.reserve(m_totalLength);
    for (const FieldDetail& f : m_schema) {
        if (f.length <= 0) {
            error = QString("字段 %1 长度非法").arg(f.name);
            return {};
        }
        // Reserved：不取值，直接填空格
        if (f.type == FieldType::Reserved) {
            buffer.append(f.length, ' ');
            continue;
        }
        // 取值；缺值 = 无法采集
        auto it = values.find(f.name);
        if (it == values.end()) {
            if (f.type == FieldType::Numeric)
                buffer.append(f.length, '0');
            else
                buffer.append(f.length, ' ');
            continue;
        }
        QByteArray fieldBytes;
        if (!encodeField(it.value(), f, fieldBytes, error))
            return {};
        buffer.append(fieldBytes);
    }
    return buffer;
}
```

## 9\. 测试建议

### 9\.1 单元测试方向

1. **Numeric 正常路径**

    - 整数、小数、恰好 scale 位、不足 scale 位。

2. **Numeric 边界**

    - 最大值、最大值 \+1（溢出）、四舍五入进位、全 9 进位。

3. **Numeric 异常**

    - 负数、非法字符、空串、多小数点。

    - 短于 length、等于 length、长于 length。

5. **Reserved**

    - 固定输出，忽略传入值。

6. **缺值**

    - Numeric 填 0、Chars 填空格。

7. **整体**

    - 多字段顺序拼接、总长度与 `totalLength()` 一致。

    - `error` 在成功时为空、失败时非空。

### 9\.2 属性测试（可选）

- 任意合法 Numeric 输入，输出长度恒等于 `length`。

- 任意合法输入，输出总长度恒等于 `totalLength()`。

- 输出字节均在 ASCII 可见范围（0x20–0x7E），Reserved/Chars 补位是空格。

### 9\.3 回归重点

- 四舍五入进位导致位数增加，是否正确走溢出分支。

- 小数位不足时补 0 的位置（补在小数侧，不是整数侧）。

## 10\. 扩展方向

### 10\.1 外部头组装纳入 schema

当前电文头（29 字节）由调用方拼装。若头部结构固定且字段较多，
可以复用同一模式再做一个 `HeaderBuilder`，最终：

```C++
QByteArray packet = headerBuilder.build(headerValues, err)
                  + dataBuilder.build(dataValues, err)
                  + QByteArray(1, 0x0A);
```

或抽象一个统一的 `MessageComposer`，把“头 \+ 数据 \+ 尾”作为三段组合。

### 10\.2 更多字段类型

- **BCD 码**：每字节两位十进制。

- **二进制整数/浮点**：如果协议某段不是 ASCII，而是原始二进制。

- **位域**：一个字节内拆成多个标志位。

### 10\.3 校验字段

很多协议在数据段内或头部带校验和（如累加和、CRC）。
可增加“后处理钩子”：

```C++
builder.setPostProcessor([](QByteArray& data, QString& err) {
    // 计算校验和并填入指定位置
});
```

### 10\.4 变长字段

当前所有字段定长。若协议存在“长度由前序字段决定”的字段，
可增加 `lengthFieldRef` 等描述，或把变长部分作为 `Raw` 由外部拼好。

### 10\.5 值与默认值的区分

当前“未传值”与“传空值”都会走缺值逻辑。若需要区分，可把
`QHash<QString, QString>` 换成 `QHash<QString, std::optional<QString>>`，
或增加显式的“已采集/未采集”标志。

### 10\.6 错误码化

当前错误通过 `QString& error` 带出，便于人读。若调用方需要程序化判断，
可扩展为 `enum class BuildError` \+ 错误信息结构体，兼顾机器判断与日志可读性。

## 12\. 字段占位、对齐与长度约束

### 12\.1 字段占位的含义

`FieldDetail.length` 表示该字段在报文里**占用的字节数**，是**固定占位**：

- 字段编码后的字节数**恒等于**`length`，不多不少。

- 值不够长 → 按类型补位；值超长 → 按规则处理（见下）。

- 所有字段 `length` 之和 = 数据内容总长度 = `DataContentBuilder::totalLength()`。

**注意**：`length` 不是“值最多多少字节”，而是“值 \+ 补位 = 这个数”。

### 12\.2 对齐规则

编码时按字段类型采用不同对齐方式，对应协议规则第 3、4 条。

#### 12\.2\.1 数值型（Numeric）——规则 3

数值型数据用 `N` 表示，采用**右对齐**方式，不足的位数在**`0`****左边补 **。

|输入|length|scale|输出|说明|
|---|---|---|---|---|
|`"123"`|5|0|`"00123"`|左补 0|
|`"53.167"`|5|3|`"53167"`|放大后刚好 5 位|
|`"53.1"`|5|3|`"53100"`|放大后 4 位，左补 0|
|`"1"`|5|0|`"00001"`|左补 0|

**`'0'`****右对齐 \+ 左补 **，输出长度恒为 `length`。

#### 12\.2\.2 字符型（Chars）——规则 4

字符型数据用 `C` 表示，采用**左对齐**方式，不足的位数在**右边补空格**。

|输入|length|输出|说明|
|---|---|---|---|
|`"z01"`|5|`"z01  "`|右补空格|
|`"ab"`|5|`"ab   "`|右补空格|
|`"abcde"`|5|`"abcde"`|刚好填满|
|`"abcdef"`|5|报错|超长|

**左对齐 \+ 右补空格**，输出长度恒为 `length`。

#### 12\.2\.3 预留（Reserved）——规则 5

预留的数据内容设置成空格，输出恒为 `length` 个空格。

### 12\.3 编码结果汇总

|类型|占位|对齐|补位字符|超额默认|缺值|超长可选|
|---|---|---|---|---|---|---|
|Numeric|`length`|右对齐|左补 `'0'`|`FillChar('9')`|填 `'0'`|`Truncate` / `Error`|
|Chars|`length`|左对齐|右补空格|`Error`|填空格|`Truncate` / `FillChar`|
|Reserved|`length`|—|填空格|—|填空格|—|

### 12\.4 长度约束（按类型）

各类型字段的 `length` 有明确约束，规避编码异常、数值溢出、内存占用过大等问题。

#### 12\.4\.1 通用约束

- 所有字段：`length > 0`，否则直接报错。

- 所有字段：`length` 必须为正整数，且整体不超过数据区最大长度上限。

#### 12\.4\.2 Numeric 的 `length` 上限

Numeric 的溢出判断需要计算 `10^length - 1`，而 `qint64` 可表示的最大值约为 `10^18`，超出该范围会导致溢出判断失效、数值计算异常。

因此强制约束：**`length ≤ 18`**。若协议业务数值范围更小，可配置更严格的上限。字段长度超限时，组装失败并返回错误信息。

```cpp
case FieldType::Numeric: {
    if (f.length > 18) {
        error = QString("字段 %1 数值长度超限（%2 > 18）")
                    .arg(f.name).arg(f.length);
        return false;
    }
    // 后续编码逻辑
}
```

#### 12\.4\.3 Chars 的 `length`上限

字符型字段无单独数值上限，理论最大长度等于数据区整体上限。仅需注意过大的 `length`会增加内存分配开销，建议根据业务场景合理配置。

#### 12\.4\.4 Reserved 的 `length` 上限

与字符型字段一致，理论上限为数据区最大长度，无额外约束。

### 12\.5 数据区总长约束

协议明确规定：**数据内容最大 8162 字节**（不含29字节电文头与 `0x0A` 结束符）。组装器默认沿用该协议上限，同时支持自定义配置，适配不同场景需求。

#### 12\.5\.1 类结构改造（支持自定义最大长度）

```cpp
class DataContentBuilder {
public:
    explicit DataContentBuilder(QVector<FieldDetail> schema,
                                int maxLength = 8162);
    // 其余接口不变
private:
    int m_totalLength = 0;
    int m_maxLength = 8162;
};
```

#### 12\.5\.2 超长校验逻辑

组装器在执行 `build()` 方法时，会优先校验数据内容总长度，超限直接终止组装并返回错误。

```cpp
QByteArray DataContentBuilder::build(...) const
{
    error.clear();
    if (m_totalLength > m_maxLength) {
        error = QString("数据内容超长：%1 > %2")
                    .arg(m_totalLength).arg(m_maxLength);
        return {};
    }
    // 后续字段组装逻辑
}
```

#### 12\.5\.3 超限行为

数据内容总长度超过配置的 `m_maxLength` 时，返回空 `QByteArray`，并通过 `error` 参数输出详细超限原因。

### 12\.6 错误处理汇总

|场景|处理|
|---|---|
|字段 `length ≤ 0`|返回空 \+ error|
|Numeric `length > 18`|返回空 \+ error|
|Numeric 输入含非法字符|返回空 \+ error|
|Numeric 输入为负数|返回空 \+ error|
|Numeric 输入为空|返回空 \+ error|
|Numeric 位数 \> length|按 `OverflowPolicy`（默认 `FillChar('9')`）|
|Chars 超长|按 `OverflowPolicy`（默认 `Error`；兼容旧逻辑用 `Truncate`）|
|数据内容总长 \> maxLength|返回空 \+ error|
|字段缺值|按类型填默认值，不报错|
|Reserved 字段传值|填空格，忽略传入值，不报错|

### 12\.7 说明

- **`length`**** 是固定占位而非上限**：所有字段编码后字节数严格等于配置的 `length`，通过补位、截断、溢出填充等规则统一保证长度固定。

- **Numeric 18位长度上限**：为底层技术约束，规避 `qint64` 数值溢出问题，保障数值解析、进位、溢出判断逻辑准确。

- **超额策略可配（规则 7）**：Numeric 默认 `FillChar('9')`；Chars 默认 `Error`；复现旧 `memcpy` 静默截断时 Chars 用 `Truncate`。

- **数据区8162字节上限**：源自设备通信协议标准，支持自定义配置，适配拓展场景。

- **统一兜底规则**：缺值按类型填默认、预留填空格；超额行为由 `OverflowPolicy` 显式决定，边界可控。

## 11\. 外部头部组装（HeaderBuilder）

### 11\.1 职责边界

头部组装器 `HeaderBuilder` 只负责**按 schema 把值填到头部指定位置**，不参与任何跨段计算或协议逻辑。

**只做**：

- 按字段描述把值编码后写入指定 `offset`。

- 按类型编码（Numeric / Chars / Reserved）。

- 缺值按类型填默认（Numeric 填 `'0'`，Chars / Reserved 填空格）。

- 头部总长度显式指定，未覆盖区域（空洞）填**默认填充字符**。

- 出错返回空 `QByteArray`，错误经 `QString& error` 带出。

**不做**（全部由调用方负责）：

- 校验和 / CRC 的计算。

- “数据段长度”等跨段依赖字段的计算。

- 结束符 `0x0A` 的拼接。

- 头 \+ 数据 \+ 尾的整体编排。

校验和、长度这类字段，由调用方算好后作为**普通字段值**传入 `values`，`HeaderBuilder` 只当它是一个待填的数值或字符。

### 11\.2 头部字段类型

头部字段类型在数据段三种类型基础上，不含 `Fixed`，只保留三种，编码规则与数据段完全一致：

|类型|说明|编码方式|
|---|---|---|
|`Numeric`|ASCII 数值型|右对齐左补 `'0'`，支持 scale / rounding，超额按 `OverflowPolicy`（默认填 `'9'`），缺值填 `'0'`|
|`Chars`|ASCII 字符型|左对齐右补空格，超额按 `OverflowPolicy`（默认报错；兼容旧逻辑用 `Truncate`），缺值填空格|
|`Reserved`|预留|全部填空格|

三种类型的编码规则与数据段**完全一致**，共用同一套 `encodeField` 逻辑。

### 11\.3 头部字段描述

```C++
// 头部字段类型（无 Fixed）
enum class HeaderFieldType {
    Numeric,    // ASCII 数值型
    Chars,      // ASCII 字符型
    Reserved,   // 预留，填空格
};

// 单个头部字段描述
struct HeaderField {
    QString         name;
    HeaderFieldType type     = HeaderFieldType::Reserved;
    int             offset   = -1;                    // 在头部中的起始位置
    int             length   = 0;                     // 字节数
    int             scale    = 0;                     // 10^-scale，仅 Numeric
```

### 11\.5 完整实现

```C++
HeaderBuilder::HeaderBuilder(QVector<HeaderField> schema,
                             int totalLength,
                             char holeFill)
    : m_schema(std::move(schema))
    , m_totalLength(totalLength)
    , m_holeFill(holeFill)
{
}

QByteArray HeaderBuilder::build(const QHash<QString, QString>& values,
                                 QString& error) const
{
    error.clear();
    if (m_totalLength <= 0) {
        error = "头部总长度非法";
        return {};
    }

    // 1. 预分配整块，空洞默认用 m_holeFill 填充
    QByteArray buffer(m_totalLength, m_holeFill);

    // 2. 逐字段填充
    for (const HeaderField& f : m_schema) {
        // 偏移 / 长度校验
        if (f.offset < 0 || f.length <= 0 ||
            f.offset + f.length > buffer.size()) {
            error = QString("头部字段 %1 偏移越界（offset=%2 len=%3）")
                        .arg(f.name).arg(f.offset).arg(f.length);
            return {};
        }

        QByteArray fieldBytes;
        switch (f.type) {
        case HeaderFieldType::Reserved: {
            // 预留：填空格
            fieldBytes = QByteArray(f.length, ' ');
            break;
        }
        case HeaderFieldType::Numeric:
        case HeaderFieldType::Chars: {
            auto it = values.find(f.name);
            if (it == values.end()) {
                // 缺值 = 无法采集
                if (f.type == HeaderFieldType::Numeric)
                    fieldBytes = QByteArray(f.length, '0');
                else
                    fieldBytes = QByteArray(f.length, ' ');
            } else {
                // 复用数据段的编码逻辑
                FieldDetail tmp;
                tmp.name     = f.name;
                tmp.type     = (f.type == HeaderFieldType::Numeric)
                               ? FieldType::Numeric
                               : FieldType::Chars;
                tmp.length   = f.length;
                tmp.scale    = f.scale;
                tmp.rounding = f.rounding;

                if (!encodeField(it.value(), tmp, fieldBytes, error))
                    return {};
            }
            break;
        }
        }

        // 3. 写入指定偏移
        buffer.replace(f.offset, f.length, fieldBytes);
    }

    return buffer;
}
```

说明：`encodeField` 是从数据段抽出到公共文件的函数，签名和实现与数据段一致。`HeaderBuilder` 和 `DataContentBuilder` 共用它。

### 11\.6 与数据段的共用与差异

|项|数据段 `DataContentBuilder`|头部 `HeaderBuilder`|
|---|---|---|
|定位方式|顺序拼接|按 `offset` 绝对定位|
|总长度|由 schema 累加|显式传入|
|空洞|无|用`holeFill` 填充（默认空格）|
|字段类型|Numeric / Chars / Reserved|同左|
|编码逻辑|`encodeField`|复用同一 `encodeField`|
|缺值策略|同左|同左|
|溢出策略|同左|同左|

### 11\.8 边界行为一览

#### 11\.8\.1 字段偏移

|场景|结果|
|---|---|
|`offset < 0`|返回空 \+ error|
|`length ≤ 0`|返回空 \+ error|
|`offset + length > totalLength`|返回空 \+ error|
|字段间重叠|**不检查**，后写覆盖先写（按 schema 顺序）|
|字段间有空洞|空洞保留 `holeFill` 字符|

#### 11\.8\.2 Numeric / Chars / Reserved

编码行为与数据段完全一致，参见第 8 章边界表。

#### 11\.8\.3 头部整体

|场景|结果|
|---|---|
|正常组装|返回长度恒为 `totalLength` 的字节|
|全部字段成功|`error` 为空|
|任一字段失败|返回空 \+ error|
|`totalLength ≤ 0`|返回空 \+ error|

### 11\.9 说明

- **`Fixed`****不做  类型**：头部若日后需要固定二进制字节（如同步字），可扩展 `HeaderFieldType::Fixed` 并加 `fixedValue` 字段。

- **空洞默认空格**：构造时通过 `holeFill` 参数自定义（如 `'\0'`）。

- **重叠字段**：当前不检查，按 schema 顺序后写覆盖先写。若需要“重叠即报错”，可在构造或 `build` 时做区间两两比较。

- **校验和 / 长度**：由调用方计算后作为普通字段传入，`HeaderBuilder` 不感知。
